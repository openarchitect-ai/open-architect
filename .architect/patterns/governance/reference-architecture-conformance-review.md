# Reference Architecture Conformance Review

## Purpose

Review solutions explicitly against relevant reference architecture guidance so
alignment, justified variance, and remediation needs are understood before
delivery proceeds too far.

## When To Use

- a solution should align with an established reference architecture
- governance needs a repeatable way to assess conformance
- major deviations could affect risk, interoperability, or long-term support

## When Not To Use

- no meaningful reference architecture exists for the scope
- the review would duplicate lower-value checks without influencing decisions

## Assumptions

- applicable reference guidance can be identified clearly
- reviewers can distinguish true variance from acceptable local tailoring
- review outcomes will drive decisions or remediation

## Key Components

- relevant reference architecture scope
- conformance criteria
- documented variances and rationale
- follow-up actions or approval outcomes

## Benefits

- improves consistency of architecture governance
- makes alignment and divergence more visible
- supports better reuse of proven architecture approaches

## Tradeoffs

- adds review effort
- can become bureaucratic if criteria are vague
- requires the reference architecture itself to be usable and current

## Common Risks

- review done too late to influence the design meaningfully
- conformance judged superficially without understanding local constraints
- variances noted but not followed through
