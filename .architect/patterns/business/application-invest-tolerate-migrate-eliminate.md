# Application Invest Tolerate Migrate Eliminate

## Purpose

Classify applications against a simple portfolio action model so investment,
retention, migration, and retirement choices can be made more consistently.

## When To Use

- the application estate needs rationalization or roadmap direction
- leaders need a common language for portfolio decisions
- architecture work must distinguish strategic assets from technical debt or
  retirement candidates

## When Not To Use

- the portfolio is too immature for comparative classification
- the model would be treated as a substitute for deeper analysis on critical
  applications

## Assumptions

- applications can be assessed against agreed criteria
- portfolio classifications will influence funding and transition decisions
- stakeholders accept that classification may change over time

## Key Components

- application inventory and scope
- classification criteria
- action category for each application
- follow-through roadmap and ownership

## Benefits

- improves clarity of portfolio direction
- supports more consistent investment and retirement conversations
- helps expose where modernization attention is most needed

## Tradeoffs

- simple categories can hide nuance
- repeated reassessment is needed as context changes
- classifications can be politically sensitive

## Common Risks

- weak or inconsistent criteria
- classification without follow-through action
- treating tolerated applications as risk-free by default
