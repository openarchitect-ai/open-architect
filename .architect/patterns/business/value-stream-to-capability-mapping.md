# Value Stream To Capability Mapping

## Purpose

Relate business value streams to the capabilities that enable them so
prioritization, gap analysis, and solution scope can be anchored to how value
is created and delivered.

## When To Use

- business transformation needs a stronger end-to-end value perspective
- capability planning should reflect customer or operational value flow
- multiple capabilities contribute to one important outcome stream

## When Not To Use

- the initiative is too small to justify end-to-end value-stream analysis
- the mapping would be produced mechanically without influencing decisions

## Assumptions

- value streams can be identified meaningfully
- the capability model is clear enough to map against
- the mapping will be used for prioritization or architecture framing

## Key Components

- value stream stages or flow
- mapped enabling capabilities
- bottlenecks, pain points, or gaps
- prioritization implications for change

## Benefits

- links business flow to architecture planning
- helps expose capability gaps in context
- supports stronger prioritization and communication

## Tradeoffs

- adds business-analysis effort
- can become abstract if not tied to decisions
- requires shared vocabulary across business and architecture teams

## Common Risks

- overcomplicating value streams without practical use
- weak linkage from mapping to roadmap or solution choices
- confusing processes, journeys, and capabilities
