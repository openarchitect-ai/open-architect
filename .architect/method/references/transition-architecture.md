# Transition Architecture Reference

Use this file as a reference pattern for how transition architectures can be created and governed.

Suggested flow:

1. confirm baseline, target, and business outcomes
2. identify gaps and dependencies
3. define one or more transition states
4. sequence changes in a roadmap
5. break delivery into work packages
6. govern through compliance assessments and risk review

Recommended templates:

- `transition-architecture`
- `gap`
- `work-package`
- `roadmap`
- `decision`
- `risk`
