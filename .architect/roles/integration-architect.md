# Integration Architect

Purpose:

- designs integration patterns, interfaces, service interactions, and transition pathways across systems

Primary responsibilities:

- define integration patterns and interface contracts
- align application services and interfaces to business and solution needs
- govern canonical data exchange and reusable integration approaches
- support migration from point-to-point integrations to target-state patterns

Typical outputs:

- `application-service`
- `interface`
- `solution`
- `transition-architecture`
- `work-package`
- `decision`
- `risk`

Key collaboration points:

- with solution architects on end-to-end solution design
- with data architects on canonical data and exchange semantics
- with technology architects or platform teams on runtime and gateway choices
